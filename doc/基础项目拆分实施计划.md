# SuperConnectX 基础项目拆分实施计划

## 目标

在**不破坏现有连接、终端、串口功能**的前提下，将通用桌面应用能力沉淀为可复用基础层。最终新应用只需要实现业务页面、业务存储和业务 IPC，即可获得统一的窗口、标题栏、侧栏、选项卡、分屏、状态栏、主题、设置、备份恢复、日志和更新能力。

## 原则

- 采用渐进式迁移：每一步完成后保持应用可运行、类型检查和测试通过。
- 基础层只提供通用能力，不依赖串口、Telnet、FTP、终端或命令管理。
- 所有业务功能保留在 `features`/现有业务目录，通过明确的接口接入基础层。
- IPC 使用显式白名单；渲染进程不直接访问 Node 或业务实现。
- 先在当前仓库内形成内部基础层；至少被第二个应用实际使用后，再考虑独立 npm 包或模板仓库。

## 实施步骤

### 步骤 1：确定边界并建立内部基础层骨架

**目标**：在当前项目中建立基础层目录、模块职责和依赖约束，不改变现有行为。

**新增目录建议**：

```text
src/
  core/                 # Electron 主进程通用基础设施
    paths/
    logging/
    window/
    tray/
    storage/
    backup/
    updater/
    ipc/
  shared/               # 跨 main/preload/renderer 的类型与契约
    ipc/
    settings/
    workbench/
  renderer/src/
    foundation/         # 渲染进程通用能力
      theme/
      i18n/
      settings/
      workbench/
      shell/
```

**本步骤产出**：

- 基础层目录和 `README`/边界说明。
- 依赖约束：`core` 不得依赖连接协议；`foundation` 不得直接调用 `window.connectApi`。
- 迁移清单与旧模块到新模块的映射。

**验收**：不改变运行结果；`npm run typecheck` 和现有测试通过。

---

### 步骤 2：抽取核心运行时服务

**目标**：将所有 Electron 桌面应用都会使用的主进程服务抽到 `src/core`。

**迁移范围**：

| 能力 | 现有来源 | 新模块 |
| --- | --- | --- |
| 数据目录、多实例、测试目录覆盖 | `src/main/utils/AppDir.ts` | `src/core/paths/AppPaths.ts` |
| 日志轮转和渲染日志桥接 | `src/main/ipc/IpcAppLogger.ts` | `src/core/logging/LoggerService.ts` |
| 无边框窗口及窗口操作 | `src/main/ipc/IpcMain.ts`、`IpcWindow.ts` | `src/core/window/WindowManager.ts` |
| 托盘与最小化到托盘 | `src/main/ipc/IpcTray.ts` | `src/core/tray/TrayManager.ts` |
| 自动更新 | `src/main/updater/AppUpdater.ts` | `src/core/updater/UpdateService.ts` |

**改造要求**：

- 使用构造函数配置应用名、图标、窗口尺寸、关闭策略和发布策略。
- 不再使用单例作为唯一接入方式；保留兼容包装，逐步改为服务实例注入。
- 保持现有 IPC 通道兼容，避免一次性修改渲染层。
- 旧版本数据迁移仅留在 SuperConnectX 的兼容代码中，不纳入基础项目。

**验收**：窗口、托盘、日志、更新检查行为与当前一致；相关单元测试迁移并通过。

---

### 步骤 3：统一存储、备份恢复和 IPC 合约

**目标**：建立通用、类型安全、可注册的设置与数据服务。

**迁移范围**：

| 能力 | 现有来源 | 改造方向 |
| --- | --- | --- |
| 通用 JSON 存储 | `src/main/storage/BaseStorage.ts` | 泛型 `StoreRepository<T>` 与可配置目录 |
| 应用偏好和会话 | `AppSettingsStorage.ts` | 基础 `PreferenceStore` |
| 设置默认值和合并 | `SettingsStorage.ts` | 可注册 `SettingsRegistry` |
| 自动备份和恢复 | `BackupManager.ts` | `BackupService`，支持元数据和保留策略 |
| ZIP 导入导出 | `IpcStorage.ts` | `DataTransferService`，由业务模块注册导出项 |
| preload 声明与暴露 | `src/preload/index.ts`、`index.d.ts` | `shared/ipc` 单一契约源 |

**改造要求**：

- 保留当前 `window.storageApi` 兼容接口；新增模块使用新的类型化接口。
- 设置分为：基础设置、工作台设置、业务设置。业务模块自行注册表单和默认值。
- 备份恢复前创建恢复前快照；导入包记录格式与版本。

**验收**：已有存储数据可读；备份、恢复、导入导出测试通过；新旧 IPC 可并行使用。

### 步骤 4：抽取工作台 UI 壳

**目标**：形成不含连接/终端业务的可复用 Vue 工作台界面。

**目标模块**：

| 模块 | 现有来源 | 改造后的职责 |
| --- | --- | --- |
| `AppShell` | `App.vue` 布局部分 | 标题栏、侧栏、主工作区、状态栏插槽 |
| `TitleBar` | `CustomTitleBar.vue` | 配置化菜单、窗口按钮、插槽操作区 |
| `SidebarLayout` | `ConnectionSidebar.vue` 外壳 | 宽度、收起、底部区域、内容插槽 |
| `WorkbenchTabBar` | `components/app/TabBar.vue` | 拖拽、固定、关闭、上下文菜单事件 |
| `SplitWorkspace` | `SuperSplit.vue`、`useSplitPanel.ts` | 分屏、比例、面板插槽 |
| `StatusBar` | `App.vue` | 左/中/右插槽 |
| `NotificationCenter` | `NotifyContainer.vue` | 通用通知服务 |
| `ThemeProvider` | `color.css`、标题栏主题逻辑 | `light/dark/system`、持久化和 DOM 应用 |

**改造要求**：

- 基础组件只能通过 `props`、`emits`、插槽和命令回调与业务交互。
- Tab 模型定义在 `src/shared/workbench`，不得包含 `connectionType`、`host`、`comName` 等领域字段。
- 将当前连接终端的关闭、重连等逻辑下沉至业务适配器。

**验收**：SuperConnectX 使用新 UI 壳后，标签拖拽、固定、关闭、分屏、会话恢复与主题切换行为保持一致。

**当前进度**：已完成 `ThemeProvider` 的主题控制器、通用分屏状态和 `SplitWorkspace`、`AppShell`、`SidebarLayout`、`SettingsLayout`、`SettingsRegistry`、三段式 `StatusBar`、侧栏拖拽调整逻辑、事件驱动的 `WindowTitleBar`、`NotificationCenter` 通知队列，以及 `WorkbenchTabBar` 的纯展示、拖拽排序和事件契约。当前 `TabBar.vue` 是 SuperConnectX 的业务适配器，负责协议图标、连接状态、串口备注和连接操作菜单；`SuperSplit.vue` 仅保留本地化和旧事件兼容；`ConnectionSidebar.vue` 通过 `SidebarLayout` 提供连接内容和业务底栏；`SettingsPage.vue` 通过 `SettingsLayout` 和 `SettingsRegistry` 注册并持有各业务设置表单和持久化；`CustomTitleBar.vue` 通过 `WindowTitleBar` 插槽保留应用菜单、主题选择和 Electron IPC 适配；`NotifyContainer.vue` 仅保留本地化兼容适配。

### 步骤 5：迁移 SuperConnectX 业务为功能模块

**目标**：让连接工具成为基础壳上的一个具体应用实现。

**目标结构**：

```text
src/renderer/src/features/
  connection/          # 连接列表、连接编辑、连接存储适配
  terminal/            # COM/Telnet/FTP 终端
  commands/            # 命令编辑、命令历史、快捷命令
  virtual-port/        # 虚拟串口
  diagnostics/         # 数据校验、日志过滤
```

**保留为业务模块的内容**：

- COM、Telnet、FTP、SSH 等协议实现及 Worker Pool。
- 连接实体、连接表单、连接侧边栏的内容区域。
- 终端、ANSI、Monaco、CRC、语法高亮。
- 命令管理、虚拟串口和 SuperCom 数据迁移。

**当前进度**：已建立 `features/connections`，连接 CRUD、连接侧栏状态、串口备注、连接编辑对话框和连接侧栏的真实实现均已迁入该功能域；旧组件与 `composables/app` 路径仅保留兼容转发。`features/terminal` 已承载终端会话编排、显示偏好、字体、面板布局、接收文本格式化，以及 COM/Telnet/统一终端、终端控制栏和日志过滤面板的真实实现；`App.vue` 直接使用该功能域。`features/commands` 已承载命令编辑器和快捷命令真实实现；`features/virtual-port` 已承载虚拟串口页面真实实现；`features/shortcuts` 已承载快捷键业务编排。渲染端连接协议实体已迁入 ## 当前实施顺序

1. 完成步骤 1，建立明确目录、边界与映射。
2. 执行步骤 2，优先迁移路径、日志和窗口服务。
3. 完成步骤 3 后再切换 IPC 与设置服务，确保数据兼容。
4. 基础运行时稳定后执行步骤 4，避免 UI 与底层同时大改。
5. 最后执行步骤 5、6，形成真实可复用模板。
